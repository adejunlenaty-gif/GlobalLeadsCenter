## What Lovable manages

Rules outside this block are the project's own. Change the pieces below in
Lovable, not by hand. With the [Lovable MCP](https://mcp.lovable.dev)
connected, `send_message` asks Lovable to do it; otherwise ask the user to
use the editor.

- **Database.** Do not add or edit `supabase/migrations/` or `drizzle/`.
  Ask Lovable to change the schema.
- **Generated files.** Do not edit a file whose header says it is automatically
  generated.
- **AI gateway.** Keep model calls on Lovable's gateway, and keep
  `LOVABLE_API_KEY` out of browser code.
- **Connectors.** Lovable provides native connectors. `list_connectors` shows
  which are enabled; `add_connector` only returns the dashboard link. When a
  connector is enabled, calls go through the connector gateway and need
  `LOVABLE_API_KEY`. When Lovable does not provide one, users can bring their
  own key and store it in Secrets.
- **Secrets.** Lovable manages them. Do not put secret values in the repo.

- Quote requests are inserted from the browser into an insert-only table (no public reads); why: simple, safe lead capture.
- Public portfolio media uses CDN pointers and opaque pixel redaction before upload; why: visitors must never receive underlying private lead records.
- Public portfolio videos remove audio and permanently cover private record areas before upload; why: original recordings can disclose contacts visually or through sound.
- Legacy gold/navy utility names map to the current semantic palette; why: shared tokens keep existing pages consistent without changing business flows.
- Service cards, detail pages and quote selections use shared service data; why: campaign standards and selected services stay consistent across the buyer journey.
- Service detail routes unnest from the directory and reuse one detail view; why: full detail pages must not render inside the directory grid.
